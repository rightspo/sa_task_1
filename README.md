# Задание для СА №1

## Введение

В задании приведён кейс, который Вам, как системному аналитику, следует решить. В ходе проработки задания Вы научитесь работать с диаграммами последовательности(sequence), OpenApi спецификациями(Swagger), тестировать запросы с помощью Postman/Insomnia, познакомитесь с термином “мок” и научитесь его делать самостоятельно.

## Глоссарий

- PlantUML — инструмент для описания диаграмм в формате кода. Подробнее можно почитать на [официальном сайте](https://plantuml.com/ru/);
- Sequence диаграмма - графическое отображение взаимодействия объектов в системе. Подробнее можно почитать в [статье на habr](https://habr.com/ru/companies/X5Tech/articles/821687);
- OpenApi - стандарт для машиночитаемого описания API. Подробнее можно почитать в [статье на habr](https://habr.com/ru/companies/first/articles/973186);
- Swagger - инструмент для отображения OpenApi спецификации;
- Postman/Insomnia — инструмент для тестирования и документирования API;
- Мок(от англ. "mock") - компонент, имитирующий реальное API. Часто применяется в разработке для тестирования front/мобильных приложений пока не готово требуемое API.

## Бизнес описание

Вам необходимо разработать микросервис, который будет отвечать за доступность и бронирование авто в сервисе каршеринга.

Функции, которые должны быть в приложении:

- Отображение автомобилей на карте;
- Отображение детальной информации авто;
- Фильтрация авто по цвету и количеству мест;
- Бронь авто;
- Старт аренды;
- Окончание аренды;
- Добавление новой карты;

## Задание

Необходимо на основании бизнес описания описать 2-3 API, желательно разного типа: POST, GET и т.д.

Для каждого API следует:

- Создать Sequence диаграмму в PlantUML;
- Создать OpenApi спецификацию;
- Мок в сервисе [quickmock](https://quickmock.dev/?lang=ru);
- Проверить в Insomnia/Postman работоспособность мока.

> Наполнение и логика работы каждого API определяется студентом. У каждого API должна быть небольшое описание в отдельном .md файле или в OpenApi спецификации

### На что обратить внимание

Если Вы хотите усложнить себе задачу, то можете реализовать дополнения из списка:

#### Sequence

- Добавить в Sequence диаграмму ассинхронную очередь, куда будут отправляться изменение статуса(любого)
- Объединить на Sequence диаграмме микросервис и БД в рамку, чтоб визуально это выглядело, как единый сервис
- Добавить альтернативные сценарии для обработки ошибок через `alt`/`opt` сценарии

#### OpenApi

- В OpenApi спецификации добавить авторизацию с помощью JWT-токена/логина и пароля
- Прописать обработку различных кодов ошибок: 400, 401, 403, 429, 500 и т.д.
- Добавить пагинацию для запроса списков
- Добавить идемпотентность в запросы POST

#### Postman/Insomnia

- Настроить переменные окружения в Postman/Insomnia, имитируя работу с ПРОДом и ТЕСТом
- Добавить автоматически генерируемые параметры(UID, числа, слова и т.д.) в запросы
- Добавить проверку негативных тест-кейсов
